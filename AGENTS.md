# Инструкции для агентов

Локальный справочник карьеры программистов 1С: Next.js 15, React 19, Drizzle, `node:sqlite`. Процесс доработки и смысл проверок — `docs/workflow.md`. Этот файл — порядок действий агента, независимо от инструмента.

## Что прочитать перед правкой

- Всегда: `CONTEXT.md`, `docs/engineering-decisions.md`.
- Профили и `seed/`: `docs/content-decisions.md`, `docs/seed-contract.md`.
- Правило предметной области: `docs/adr/`.
- Правила стека и уже пойманные сбои: `.cursor/rules/*.mdc` — обычный markdown, читать в любом инструменте. Особенно `learned-cases.mdc`.

## Неизменные правила

- Профиль стажёра остаётся в seed. Заполненных профилей семь: intern, junior, programmer, senior, lead, architect, team-lead.
- Уровни компетенций не выводить из шапки схем и не нумеровать по грейду.
- ИПР — отдельный документ `/idps`, задания — `/assignments`. Не раздел карточки сотрудника.
- Внутренние ссылки — `<a href>`, не `next/link`. Вход и выход — POST `/api/session`.
- Секреты, `.env.local`, `*.sqlite`, `tmp/` в git не класть.
- Файлы в `.cursor/plans/` не править.

## Задание «сделай issue N»

1. **Прочитать issue** доступным инструментом GitHub (MCP, `gh`, API). Спросить человека до кода, если:
   - нет критериев приёмки или они допускают два прочтения;
   - задача меняет правило предметной области (нужен ADR или правка `CONTEXT.md`);
   - изменение схемы стирает строки (пересоздание таблицы, удаление колонки с данными).
   В остальных случаях работать без остановок.
2. **Ветка** `issue-<N>-<коротко>` от свежего `origin/main`. В `main` не коммитить: ветка защищена.
3. **Реализация** — минимальная, в стиле соседнего кода. Таблицы меняются в `src/db/schema.ts` и `src/db/migrate.ts` одним изменением.
4. **Тесты.**
   - На каждый критерий приёмки — тест в `e2e/` (новый или правка существующего). Негативный случай обязателен.
   - Меняются таблицы — обновить `scripts/upgrade-base.ts`, чтобы он заполнял новые колонки и таблицы.
   - Правка `seed/data.json` — синхронно `seed/fixtures/junior.json` и `scripts/extract_drawio.py`, затем `npm run db:seed`.
5. **Проверки.** Все должны пройти до коммита. Упавшую чинить, а не обходить.

   | Команда | Что проверяет |
   |---|---|
   | `npm run check:seed` | seed по контракту |
   | `npx tsc --noEmit` | типы |
   | `npm run test:e2e` | сценарии в браузере на отдельной базе `tmp/e2e.sqlite`, порт 3100 |
   | `npm run build` | сборка |

   Перед `test:e2e` и `build` остановить dev-сервер на 3000: они пишут в ту же папку `.next`. После — поднять `npm run dev` снова на 3000. Сборка за корпоративным прокси — см. `learned-cases.mdc`.
   Проверку обновления базы (`check:upgrade`) выполняет CI на базе из `main`. Локально — только если человек дал снимок: `npm run check:upgrade -- <файл>`.
6. **Коммит, push, pull request.** Описание — по `.github/pull_request_template.md`, `Closes #N`. В таблицу проверок — фактический результат команд (число тестов, ошибки), не галочки.
7. **Стоп.** Сообщить человеку ссылку на pull request и итог проверок. Всё дальнейшее — ответы на ревью, правки, merge, выкладка — только по его запросу. Merge агент не делает.

## Ответ на ревью

По запросу человека: прочитать комментарии к pull request. Каждое замечание — исправить или ответить отказом со ссылкой на ADR или правило. После правок — снова шаг 5, затем push в ту же ветку.

## Уроки

Повторяемый сбой стека, подтверждённый логом или браузером, — пункт в `.cursor/rules/learned-cases.mdc`. Продуктовое решение — `CONTEXT.md` или ADR.
