# Инженерные решения

Решения, принятые при сборке приложения. Контент профилей — в `docs/content-decisions.md`, схема JSON — в `docs/seed-contract.md`.

## Назначение

Локальный справочник должностей и профилей программистов 1С по лестнице отдела разработки. Не публичный сервис: только `localhost`.

Профиль стажёра входит в seed. Это подтверждено владельцем и не откатывается «потому что в плане было четыре грейда».

Заполненных профилей семь: intern, junior, programmer, senior, lead, architect, team-lead. Остальные узлы схемы — должности без профиля, пока нет схем и выбранных стандартов.

Приложенный план реализации не править, пока владелец сам его не откроет. Расхождения с планом фиксировать в этих документах, не в файле плана.

## Стек

- Next.js App Router, `npm run dev` слушает `127.0.0.1:3000`.
- Drizzle + SQLite. Драйвер — `node:sqlite` (`DatabaseSync`) в `src/db/sqlite.ts`. Пакет `better-sqlite3` в зависимостях — заглушка `vendor/better-sqlite3`: drizzle-адаптер импортирует это имя, нативный модуль на Windows не собирается и не ставится.
- WAL, одно соединение. Вложенные транзакции — SAVEPOINT, не вложенный `BEGIN`.
- Повторный `db:seed` не удаляет файл БД (на Windows это `EBUSY`): чистит таблицы через `DELETE`. Перед seed файл копируется в `*.bak`. Внутри `transaction()` после `BEGIN` команда `PRAGMA foreign_keys = OFF` не действует, поэтому дочерние строки удаляются до родителя: `competency_links` раньше `competencies`.

Если Next на 3000 слушает, но страница не открывается, а в `netstat` куча `CloseWait` — процесс `start-server.js` завис. Его убивают и поднимают `npm run dev` заново; второй экземпляр на 3001 не оставляют.

## Секреты и админка

`ADMIN_PASSWORD` и `SESSION_SECRET` задаются в `.env.local`. Пустые значения и плейсхолдеры `change-me` / `dev-only-change-me` код отклоняет: без секрета cookie администратора не выдаётся. Значения по умолчанию в код не возвращать. `.env.local` в git не попадает.

Пока нет ни одного сотрудника с признаком админа, `ADMIN_PASSWORD` создаёт первого. После этого пароль из окружения сессию не выдаёт: запасного входа мимо учёток нет. Доменный смысл админа и граница «каталог без входа / кабинет после входа» — в `docs/adr/0004-employee-accounts-public-catalog.md`.

Вход, выход и bootstrap первого админа — POST `/api/session` (`intent`: `login` | `bootstrap` | `logout`). Сессия ставится cookie на ответе, дальше 303 на `/me` или `/login?error=`. Не `useActionState` + `redirect`: клиент ждёт JSON и кнопка зависает («Входим…», «Создаём…»).

Ошибки инвариантов на формах справочника и пунктах ИПР показывают через `ActionForm` и `useActionState`, а не глотают исключение.

## Интерфейс

Визуальный язык — Archify Classic (токены в `src/app/globals.css`).

Типографика — правило из `CONTEXT.md`: три размера текста (`--fs-sm` / `--fs-md` / `--fs-lg` в `src/app/globals.css`), иерархия внутри шага — весом, регистром и цветом. Утилиты Tailwind `text-sm` и `text-xs` не применять: они дают четвёртый и пятый размер. Подпись ребра React Flow (`10px` в его стилях) перекрыта своей `.react-flow__edge-text`. Проверка — `e2e/typography.spec.ts`: на ключевых экранах не больше трёх вычисленных размеров и ни одного размера вне шкалы.

`rankOrder` нужен графу (колонка `lane` + сортировка внутри колонки) и админке. Пользователю его не показывают: ни на карточке должности, ни в списке на главной.

На главной нет поясняющего текста про колонки отдела разработки и цвет заполненного профиля. Легенда — сама схема.

Карточка должности на графе — обычный `<a href>` с классом `nopan`, не `next/link`. Полосы грейдов и handles React Flow не перехватывают клик (`pointer-events: none` на lanes). Клиентский `Link` глотал левый клик (страница не менялась, «открыть в новой вкладке» работало) — внутренние переходы везде обычные адреса.

ИПР в интерфейсе: список `/idps`, документ `/idps/{id}`, справочник заданий `/assignments` (руководитель и админ). Создание — на списке, с периодом. Карточка сотрудника и кабинет только ссылаются на план. Кто видит какие планы — в `docs/adr/0005-idp-is-a-document.md`. Задания и приёмка — в `docs/adr/0006-idp-assignment-acceptance.md`.

Компетенции в админке: список `/admin/competencies`, карточка `/admin/competencies/{id}`. «Новая компетенция» открывает создание. Занятый id эта форма не обновляет: правка только на карточке уже существующей компетенции.

После правок UI проверять в браузере по реальному сценарию, а не по одному скриншоту.

## Данные и генератор

Источник правды по профилям — `seed/data.json`. Исходные `.drawio` в репозитории не хранятся.

`extract_drawio.py` при повторном запуске:

- не перезаписывает `jobs` и `transitions`, если JSON уже есть;
- сохраняет ручные `criteria` и строки, которых нет в схемах;
- переносит профили вне пяти схем грейдов (`architect`, `team-lead`);
- выставляет уровни из `LEVEL_MATRIX` / `PROFILE_LEVELS` и падает, если professional/universal без 1–3 или уровень не из таблицы.

Уровни из шапки drawio не извлекаются и не выводятся из номера грейда — это фабрикация, её уже убирали.

После правки JSON локально нужен `npm run db:seed`. Обычное обновление сервера живую базу не перечитывает.

Перезапись каталога на уже работающей базе — `npm run db:sync-catalog -- <файл базы>` и ключ `-SyncCatalog` у `scripts/update-server.ps1`. Команда заново записывает компетенции и профили из `seed/data.json`: имена, группы, уровни, критерии и состав строк. Сотрудников, планы и задания не удаляет. У компетенций, которые остаются, материалы тоже остаются. Компетенцию, которой больше нет в исходниках, команда убирает вместе с её материалами, только если на неё нет заданий, пула, строк плана и личных пометок; иначе вся перезапись отменяется. Название компетенции в уже открытом плане обновляется, тексты заданий в строках плана — нет. `npm run db:seed` на живой базе по-прежнему не запускать: он стирает должности, компетенции, профили, задания и материалы.

Разовые скрипты сверки живут в `tmp/` (gitignore) и после применения удаляются.

Доработка по issue идёт по `AGENTS.md` и `docs/workflow.md`: агент сам коммитит в ветку issue и открывает pull request, `main` защищена. Вне issue коммитить только по явной просьбе. В git не класть секреты, `.env.local`, sqlite и `tmp/`.
