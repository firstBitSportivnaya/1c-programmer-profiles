# Как выложить «Профили должностей» на сервер Windows с IIS

Инструкция для человека, который ставит сайт на сервер первый раз. Команды ниже вводятся в PowerShell. Окно PowerShell открывается так: кнопка «Пуск», набрать `powershell`, правой кнопкой по «Windows PowerShell» → «Запуск от имени администратора».

В конце получится обычный сайт в браузере, например `http://170.170.170.170:44448`. Домен не нужен: люди заходят по IP и отдельному порту. Снаружи его принимает IIS. Само приложение крутит программа Node.js и слушает только этот же компьютер по адресу `http://127.0.0.1:3000`. С других компьютеров порт 3000 открывать не нужно.

Нужны права администратора на сервере и папка, куда можно положить файлы, например `C:\apps\programming-profiles`.

## Что скачать заранее

Скачать на сервер три установщика. Версии брать актуальные с сайтов Microsoft и nodejs.org.

1. Node.js **24**, установщик Windows 64-bit (LTS или Current, главное — номер 24). Адрес: https://nodejs.org/
2. IIS URL Rewrite. Адрес: https://www.iis.net/downloads/microsoft/url-rewrite
3. Application Request Routing 3 (ARR). Адрес: https://www.iis.net/downloads/microsoft/application-request-routing

Для постоянной работы ещё понадобится NSSM — маленькая программа, которая держит Node включённым после перезагрузки сервера. Адрес: https://nssm.cc/download . Из архива взять файл `win64\nssm.exe`.

## 1. Поставить Node.js

1. Запустить установщик Node.js.
2. Оставить путь по умолчанию.
3. На шаге про инструменты поставить галочку «Automatically install the necessary tools» не обязательно. Для этого приложения она не нужна.
4. Дождаться окончания и закрыть установщик.
5. Закрыть старое окно PowerShell, если оно было открыто до установки, и открыть новое от администратора.
6. Проверить:

```powershell
node -v
npm -v
```

Должно быть `v24.…` и номер npm. Если команда `node` не находится, перезагрузить сервер и проверить ещё раз.

## 2. Включить IIS

1. «Пуск» → набрать `Включение или отключение компонентов Windows`. На сервере это «Диспетчер серверов» → «Управление» → «Добавить роли и компоненты».
2. Роль **Веб-сервер (IIS)**. Внутри неё достаточно стандартного набора: «Веб-сервер», «Основные возможности HTTP», «Статическое содержимое», «Документ по умолчанию», «Обзор каталога» можно не включать.
3. Компонент «Консоль управления IIS» тоже нужен, он обычно включается вместе с ролью.
4. Дождаться установки.
5. «Пуск» → «Диспетчер служб IIS». Окно открылось — IIS стоит.

Проверка: на самом сервере открыть браузер и зайти на `http://localhost`. Должна появиться стартовая страница IIS.

## 3. Поставить URL Rewrite и ARR

1. Запустить установщик URL Rewrite, пройти мастер до конца.
2. Запустить установщик ARR, пройти мастер до конца.
3. Закрыть и снова открыть «Диспетчер служб IIS».
4. В дереве слева выбрать имя сервера (самый верхний узел, не сайт).
5. В центре должна появиться иконка **Application Request Routing Cache**. Если её нет, установщик ARR не встал: поставить ещё раз от администратора.

Включить прокси:

1. Двойной щелчок по **Application Request Routing Cache**.
2. Справа «Действия» → **Server Proxy Settings**.
3. Поставить галочку **Enable proxy**.
4. Оставить включённой галочку **Reverse rewrite host in response headers**. На этом экране отдельной настройки «Preserve host header» нет: в этой версии ARR её место занимает именно эта галочка. Она подменяет в ответе адрес `127.0.0.1` на имя сайта, чтобы после входа браузер не уезжал на адрес, который с другого компьютера не открывается.
5. Снять галочку **Enable disk cache**. Иначе IIS может запомнить страницу одного пользователя и показать её другому.
6. Справа нажать **Применить**.

## 4. Скопировать приложение на сервер

Папка на сервере: `C:\apps\programming-profiles`.

Скопировать туда проект с компьютера разработчика. Не копировать папки `node_modules` и `.next`: они соберутся на сервере заново. Не копировать `.env.local` с чужого компьютера, если там пароли для разработки. Секреты для сервера задаются отдельно, шаг 6.

Должны лежать как минимум: `package.json`, `package-lock.json`, папка `src`, папка `vendor`, папка `public` (если есть), `next.config.ts`, `tsconfig.json`, `seed`.

## 5. Собрать приложение

В PowerShell:

```powershell
cd C:\apps\programming-profiles
npm ci
npm run build
```

`npm ci` ставит библиотеки. Это несколько минут. Ошибка `node-gyp` или `better-sqlite3` значит, что поставился чужой пакет: в этом проекте `better-sqlite3` — заглушка из папки `vendor`, отдельный компилятор C++ не нужен.

`npm run build` готовит рабочую сборку. В конце должно быть сообщение об успехе и список страниц. Команду `npm run dev` на сервере не использовать: это режим разработки, он медленный и не рассчитан на постоянную работу.

## 6. Задать пароли

В папке `C:\apps\programming-profiles` создать файл `.env.local` в блокноте. Сохранить как «все файлы», имя точно `.env.local`, не `.env.local.txt`.

Содержимое, со своими значениями:

```
ADMIN_PASSWORD=сюда-длинный-пароль
SESSION_SECRET=сюда-длинная-случайная-строка
DB_PATH=data/profiles.sqlite
```

`ADMIN_PASSWORD` — пароль, которым создаётся первый администратор. Он срабатывает один раз, пока в базе нет ни одного администратора. После этого вход только логином сотрудника.

`SESSION_SECRET` — секрет подписи cookie. Любая длинная случайная строка, не слово `change-me` и не `dev-only-change-me`. Пустая строка тоже не подойдёт: сайт откроется, а войти будет нельзя.

Пример случайной строки в PowerShell:

```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

Скопировать результат в `SESSION_SECRET`. Файл `.env.local` никому не отправлять и в git не класть.

## 7. Положить базу

База — один файл SQLite. Приложение само создаст папку `data`, если её нет.

**Если на рабочем компьютере уже есть сотрудники и планы ИПР**, их нужно перенести:

1. На рабочем компьютере остановить приложение (закрыть окно, где был `npm run dev`, или остановить процесс).
2. Скопировать файл `data\profiles.sqlite` в `C:\apps\programming-profiles\data\profiles.sqlite`.
3. Если рядом лежат `profiles.sqlite-wal` и `profiles.sqlite-shm`, скопировать и их. Если приложение было остановлено, этих двух файлов может не быть — это нормально.

**Если сервер пустой и нужны только должности из поставки**, на сервере один раз:

```powershell
cd C:\apps\programming-profiles
npm run db:seed
```

Появится строка `seeded jobs=…`. Повторно эту команду на сервере с живыми данными не запускать: она удаляет должности, компетенции и профили и записывает их заново из `seed\data.json`. Сотрудников и ИПР seed не создаёт.

## 8. Проверить, что приложение запускается

```powershell
cd C:\apps\programming-profiles
npm start
```

Подождать строку `Ready` или `Local: http://127.0.0.1:3000`. На сервере в браузере открыть `http://127.0.0.1:3000`. Должна открыться «Схема развития» со списком должностей.

Окно PowerShell не закрывать, пока идёт проверка. Когда страница открылась, в этом окне нажать Ctrl+C и подтвердить остановку. Дальше приложение будет запускать служба, а не это окно.

Если страница не открывается, смотреть текст ошибки в этом же окне. Частые причины: не выполнен `npm run build`, нет файла `.env.local`, порт 3000 уже занят другой программой.

## 9. Сделать так, чтобы приложение включалось само

1. Положить `nssm.exe` в `C:\apps\nssm\nssm.exe`.
2. В PowerShell от администратора:

```powershell
C:\apps\nssm\nssm.exe install ProfilesNext
```

3. В открывшемся окне вкладка **Application**. В Path указывать `node.exe`, не `npm.cmd`: служба Windows не запускает файлы `.cmd`, поэтому `Start-Service` сразу падает.
   - Path: `C:\Program Files\nodejs\node.exe`
   - Startup directory: `C:\apps\programming-profiles`
   - Arguments: `node_modules\next\dist\bin\next start --hostname 127.0.0.1`
4. Вкладка **Details**: Display name — `Профили должностей`.
5. Вкладка **I/O** по желанию: stdout и stderr в `C:\apps\programming-profiles\logs\node-out.log` и `node-err.log`. Папку `logs` создать заранее.
6. Нажать **Install service**.
7. Запустить:

```powershell
Start-Service ProfilesNext
```

8. Подождать полминуты и снова открыть `http://127.0.0.1:3000`. Страница должна открыться уже без окна PowerShell.

Остановить службу, если понадобится: `Stop-Service ProfilesNext`. Перезапуск после обновления файлов: `Restart-Service ProfilesNext`.

Учётная запись службы по умолчанию — локальная системная. Ей нужна запись в папку `C:\apps\programming-profiles\data`. Если позже службу переведут на отдельного пользователя, этому пользователю выдать изменение на папку `data` и чтение на всю папку приложения.

Вторую копию `npm start` рядом не держать. Одна база — один процесс.

## 10. Создать сайт в IIS

1. «Диспетчер служб IIS».
2. Слева раскрыть сервер → **Сайты**.
3. Справа **Добавить веб-сайт**.
4. Имя сайта: `profiles`.
5. Физический путь: новая пустая папка, например `C:\inetpub\profiles`. В неё не класть файлы приложения. Там будет только один файл `web.config`.
6. Привязка: тип `http`, порт — свободный, например `44448`. Поле «Имя узла» оставить пустым. Домен для этого не нужен.
7. Нажать ОК.

Порт `80` и порт `44447`, если на нём уже открыт другой сайт, не занимать. Адрес вида `http://170.170.170.170:44447/profiles/` тоже не использовать: ссылки и оформление этого приложения всегда идут от корня сайта, папка в адресе их сломает. Люди открывают `http://170.170.170.170:44448` — без хвоста `/profiles/`.

Если появится окно «Привязка назначена другому сайту», нажать **Нет** и выбрать другой номер порта.

## 11. Файл web.config

В папке `C:\inetpub\profiles` создать файл `web.config`. Блокнот часто дописывает `.txt`. Проверить в проводнике, что полное имя именно `web.config`.

Вставить:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="ReverseProxyToNext" stopProcessing="true">
          <match url="(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:3000/{R:1}" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>
```

Смысл файла: любой адрес сайта IIS незаметно переписывается на приложение Node на этом же сервере.

В диспетчере IIS выбрать сайт `profiles` → в центре **URL Rewrite**. Должно быть одно правило `ReverseProxyToNext`. Если раздела URL Rewrite нет, модуль из шага 3 не установлен.

## 12. Открыть сайт с другого компьютера

На сервере в брандмауэре Windows разрешить входящие на выбранный порт, например **44448**. Правило для порта **3000** не создавать.

В браузере с другого компьютера открыть `http://170.170.170.170:44448`, подставив IP сервера и тот порт, который указан в привязке сайта.

Проверить по порядку:

1. Видна «Схема развития» и список должностей. Ссылки «Профиль» открываются.
2. Страница «Сравнение» показывает должности и таблицу.
3. «Войти». Если база новая и админа ещё нет, первый вход — паролем из `ADMIN_PASSWORD` на экране первого администратора. Если база перенесена, входить логином уже существующего сотрудника. Пароль из `.env.local` после появления администратора больше не пускает.
4. Под администратором открыть справочник или ИПР и сохранить любую мелкую правку. Если вместо сохранения ошибка доступа, у службы нет права записи в `C:\apps\programming-profiles\data`.

Адрес `http://127.0.0.1:3000` с другого компьютера открываться не должен. Так и задумано.

## 13. Если сайт должен открываться по https

Сертификат ставится на сайт IIS, не на Node.

1. В диспетчере IIS выбрать сайт → справа **Привязки** → добавить `https`, порт `443`, выбрать сертификат.
2. Службу Node не перенастраивать: она по-прежнему на `http://127.0.0.1:3000`.
3. Проверить вход ещё раз уже по `https://…`.

## 14. Как обновлять потом

Пошагово: [docs/update-server.md](update-server.md). После появления коммита в GitHub на сервере от администратора:

```powershell
powershell -ExecutionPolicy Bypass -File C:\apps\programming-profiles\scripts\update-server.ps1
```

Скрипт останавливает службу `ProfilesNext`, подтягивает изменившиеся файлы, собирает сайт и запускает службу. Файл `.env.local` и папку `data` он не трогает. `npm run db:seed` на живой базе не запускать.

## Если что-то пошло не так

| Что видно | Что сделать |
| --- | --- |
| `node` не находится | Установщик Node не дошёл до конца или PowerShell открыт с прошлого раза. Закрыть окно, открыть новое, снова `node -v`. Нужна версия 24. |
| `http://localhost` IIS не открывается | Роль IIS не включена или сайт остановлен. В диспетчере IIS у сайта состояние «Запущен». |
| `Start-Service ProfilesNext` пишет «Не удалось запустить службу» | В NSSM в Path стоит `npm.cmd`. Заменить на `node.exe`, как в шаге 9, и запустить службу снова. |
| `http://127.0.0.1:3000` не открывается | Служба `ProfilesNext` остановлена или `npm run build` не выполнялся. Смотреть `logs\node-err.log`. |
| Сайт IIS открывается, а картинка IIS «не удаётся найти страницу» или 404 IIS | Нет `web.config` или не включён proxy в ARR. |
| Сайт открывается, но стили пустые и кнопки ведут на `127.0.0.1` | В ARR на экране Server Proxy Settings выключена галочка Reverse rewrite host in response headers. Включить её и перезапустить сайт IIS. |
| Страницы есть, войти нельзя | В `.env.local` пустой `SESSION_SECRET` или слово-заглушка. Исправить файл и выполнить `Restart-Service ProfilesNext`. |
| Вход есть, сохранение падает | Нет права на запись в папку `data` у учётной записи службы. |
| После обновления старая страница | Службу не перезапустили или браузер держит старый файл. `Restart-Service ProfilesNext` и Ctrl+F5. |
